DevOps and MLOps 测验（第二批）—— 题目、选项与答案（中文）
================================================================


第 3 题
题目：一个机器学习团队使用某个数据集训练模型，达到 92% 的准确率。几周后，另一位开发人员
使用相同的代码训练同一个模型，却得到 87% 的准确率。在这种情况下，数据版本化为什么重要？

A. 数据版本化确保每次训练都产生相同的准确率，无论使用什么数据。
B. 数据版本化有助于识别每次实验所用的确切数据集，从而可以调查数据变化是否导致了差异。
C. 数据版本化会根据以往模型的准确率自动选择最佳的训练数据集。
D. 数据版本化取代了对源代码和训练配置进行记录的需要。

答案：B
解析：两次结果不同最可能与数据差异有关，版本化能定位每次实验的具体数据集，便于排查原因。

第 4 题
题目：执行 `dvc add data.csv` 后，DVC 会创建一个名为 data.csv.dvc 的文件。该文件的主要
用途是什么？

A. 它包含一份完整数据集的压缩副本，以便 Git 能高效存储。
B. 它包含训练前对数据集进行预处理所需的 Python 指令。
C. 它充当由该数据集生成的已训练模型产物。
D. 它包含元数据（含标识被跟踪数据的信息），让 Git 能够跟踪项目引用的是哪个数据集版本。

答案：D
解析：.dvc 文件是一个轻量指针/元数据文件（含哈希等信息），真正数据存放在别处，Git 通过它
记录数据集版本。

第 5 题
题目：一个机器学习项目包含多个随时间变化的大型数据集。团队已经使用 Git 管理源代码。
团队为什么可能引入 DVC？

A. Git 无法在同一个仓库中跟踪 Python 源代码和数据集元数据。
B. DVC 会自动将大型数据集转换为更小的数据集而不丢失信息。
C. DVC 允许通过 Git 中的轻量元数据对大型数据集进行版本控制，而实际内容单独管理。
D. DVC 使 Git 变得不再必要，因为它为所有项目文件提供了独立的版本控制系统。

答案：C
解析：DVC 用少量元数据纳入 Git，真实大文件存于远程，从而解决 Git 不适合存大文件的问题；
它并不替代 Git。

第 6 题
题目：一个团队配置了 CI 管道，在开发人员将更改推送到共享仓库时运行。哪种场景最能体现该
管道的价值？

A. 一位开发人员发现客户的生产数据库正在使用过时的记录。
B. 一位开发人员收到另一位团队成员创建了新分支的通知。
C. 一位开发人员推送的代码意外破坏了现有功能，自动化测试在更改被合并前报告了失败。
D. 一位开发人员手动部署了应用的新版本，并确认服务器正在运行。

答案：C
解析：CI 的核心价值是尽早自动发现集成/回归问题，即在合并前捕获坏提交。

第 7 题
题目：一位开发人员的应用由 Web 服务器、数据库和缓存服务组成。对这个应用使用 Docker Compose
的主要优势是什么？

A. 它把三个应用合并成一个单一的 Docker 镜像，从而降低资源消耗。
B. 它允许开发人员使用一个声明式配置文件一起定义、配置和管理相关服务。
C. 它自动把三个服务转换为一个进程以简化通信。
D. 它消除了为这些服务配置网络或持久化存储的需要。

答案：B
解析：Compose 用一份声明式 YAML 统一编排多服务，是其核心优势；它不合并镜像或进程，也不
免除网络/存储配置。

第 8 题
题目：考虑以下 Docker Compose 配置中的端口设置（例如 "5000:80"）。该端口配置的含义是什么？

A. 发往宿主机 5000 端口的请求被转发到容器内的 80 端口。
B. 发往宿主机 80 端口的请求被转发到容器内的 5000 端口。
C. Nginx 会自动将其内部监听端口从 80 改为 5000。
D. 该端口配置只允许容器之间通信，不允许来自宿主机的通信。

答案：A
解析：端口映射格式为 "宿主机端口:容器端口"，即把宿主机 5000 映射到容器内 80。

第 9 题
题目：Dockerfile 与 Docker Compose 配置文件的主要区别是什么？

A. Dockerfile 定义如何构建镜像，而 Docker Compose 定义服务及其容器应如何一起配置和运行。
B. Dockerfile 配置正在运行的容器，而 Docker Compose 只负责下载基础镜像。
C. Dockerfile 用于生产环境，而 Docker Compose 仅用于开发环境。
D. Dockerfile 管理应用依赖，而 Docker Compose 取代了构建或使用 Docker 镜像的需要。

答案：A
解析：Dockerfile 面向"构建镜像"，Compose 面向"编排多服务的运行配置"，这是本质区别。

第 10 题
题目：一位机器学习工程师想复现三个月前进行的一次实验。项目使用 Git 对源代码进行版本控制，
使用 DVC 对训练数据集进行版本控制。旧数据集版本在 DVC 远程存储中可用。哪种做法最合适？

A. 检出包含代码和 DVC 元数据的相关 Git 提交，然后使用 `dvc pull` 拉取相应的数据版本。
B. 检出最新的 Git 提交并获取最新的数据集，因为训练管道应当向后兼容。
C. 下载最早可用的数据集，并用最新训练代码执行以复现早期实验。
D. 在不更改数据集的情况下重新构建生产 Docker 镜像，因为容器化能确保训练数据不变。

答案：A
解析：复现需同时还原代码版本与数据版本：检出对应提交后用 dvc pull 取回匹配的数据。

第 11 题
题目：在机器学习生产系统中，模型版本化的主要目的是什么？

A. 维护源代码的不同版本，同时只保留最近训练的模型。
B. 存储模型生成的预测结果，以便模型无需再次执行。
C. 确保每个新模型自动替换先前的生产模型。
D. 识别、跟踪并管理不同的已训练模型产物，以便团队比较、部署和恢复特定版本。

答案：D
解析：模型版本化用于管理多个模型产物，支持比较、部署与回滚。

第 12 题
题目：持续交付（Continuous Delivery）与持续部署（Continuous Deployment）的主要区别是什么？

A. 持续交付只运行测试，而持续部署负责构建应用。
B. 持续交付让软件保持可随时发布的状态，但可保留人工审批步骤；持续部署则自动发布通过
   管道的更改。
C. 持续交付仅适用于开发环境，而持续部署仅适用于生产环境。
D. 持续交付要求每次更改都立即部署，而持续部署允许团队安排手动发布。

答案：B
解析：两者都自动化到可发布状态，区别在于是否保留人工审批门槛。

第 13 题
题目：一位开发人员对一个使用命名卷（named volume）保存数据库的应用运行 `docker compose down`
（关闭相应容器），未提供额外参数。通常会发生什么？

A. 容器停止，但其定义和网络被保留以便立即重启。
B. 与该工程关联的所有容器、镜像和命名卷都被删除。
C. Compose 的容器和网络被移除，但命名卷及其存储的数据被保留。
D. 只有应用容器被移除，因为 Docker 会自动保护数据库容器。

答案：C
解析：`docker compose down` 默认删除容器和网络，但保留命名卷及其数据（除非加 -v）。

第 14 题
题目：一个机器学习项目对两次实验使用完全相同的训练脚本和超参数，但第二次实验使用了修改过的
训练数据集。哪项陈述是正确的？

A. 由于源代码和超参数未变，所得模型必然完全相同。
B. 数据集变化只影响推理时的模型性能，不影响训练过程。
C. 所得模型可能不同，因为训练数据是学习过程的重要输入。
D. 只有模型架构也发生变化时，数据集变化才重要。

答案：C
解析：训练数据是模型学习的关键输入，数据不同则学到的模型通常不同。

第 15 题
题目：一个 Docker Compose 应用包含两个服务，分别名为 backend 和 db，连接到同一个 Compose
网络。backend 需要连接数据库。它通常应使用哪个主机名？

A. localhost，因为 Docker 会自动将流量重定向到相关服务。
B. 开发人员宿主机的 IP 地址。
C. 容器当前的 IP 地址，应手动记录在配置中。
D. db，因为同一 Compose 网络上的服务通常可以用服务名互相发现。

答案：D
解析：同一 Compose 网络内，服务可用服务名作为主机名进行 DNS 解析互通。

第 16 题
题目：一个 CI/CD 管道构建应用、运行测试并将其部署到 staging。一旦通过审批，同一版本必须部署
到 production。通常哪种做法更可取？

A. 在生产环境中使用最新的可用依赖独立重新构建应用。
B. 将源代码从 staging 复制到 production 并手动重新安装依赖。
C. 将经过测试的同一构建产物从 staging 晋升（promote）到 production，并应用相应的环境配置。
D. 为 production 专门创建一个新的源代码分支并从该分支重新构建应用。

答案：C
解析：应晋升同一经过测试的产物，保证"测什么就部署什么"，只替换环境相关配置。

第 17 题
题目：一个团队有一个 CI/CD 管道，在部署到 production 之前先将应用部署到 staging 环境。
这个 staging 环境的主要目的是什么？

A. 取代开发期间对单元测试和集成测试的需要。
B. 允许开发人员对已部署的应用进行未跟踪的源代码修改。
C. 确保生产服务器永远不需要环境特定的配置。
D. 在将更改暴露给真实用户之前，以接近生产环境的条件验证发布。

答案：D
解析：staging 用于在类生产环境中做发布前验证，降低上线风险。

第 18 题
题目：在软件开发团队中，持续集成（CI）的主要目标是什么？

A. 每次代码提交后立即自动部署到生产环境。
B. 推迟集成直到所有开发人员完成各自特性，以减少集成操作次数。

D. 确保开发人员独立工作，在准备发布前无需共享代码。

第 19 题
题目：一个 PostgreSQL 容器将其数据库文件存储在 Docker 命名卷中。该容器被删除并以相同卷挂载到
相应的数据库目录后重新创建。通常会发生什么？

A. 数据库会以空的状态启动，因为每个新容器都会获得新的存储。
B. Docker 会从原始 PostgreSQL 镜像重新下载数据来恢复它。
C. Docker 自动将先前容器的可写层转换为新的数据库卷。
D. 现有数据库文件仍然可用，因为命名卷的生命周期独立于容器。

答案：D
解析：命名卷独立于容器生命周期，重建容器并挂载同一卷即可保留原有数据。

第 20 题
题目：在 Docker Compose 服务定义中，使用 build 与使用 image 的主要区别是什么？

A. build 启用持久化存储，而 image 定义容器的内存使用。
B. build 指定如何从构建上下文构建镜像，而 image 指定要使用的镜像或构建所得镜像的名称。
C. build 创建多个容器，而 image 将服务限制为单个容器。
D. build 配置网络连接，而 image 决定哪些服务可以通信。

答案：B
解析：build 面向"从上下文构建镜像"，image 面向"使用已有镜像/命名构建结果"。

第 21 题
题目：在 CI/CD 过程中，为什么对部署产物（如 Docker 镜像）进行版本化并保留是有用的？

A. 它确保产物在每个运行时环境中行为完全一致，无论配置如何。
B. 它会在部署旧版本时自动应用数据库架构更改。
C. 它消除了应用打包后进行测试的需要。
D. 它让团队能够识别部署了什么，并能重新部署或回滚到某个特定的历史构建。

答案：D
解析：保留带版本的产物便于审计、重部署与回滚。

第 22 题
题目：一个部署管道需要为 staging 和 production 使用不同的凭据。管理这些凭据最合适的方式是什么？

A. 将凭据分别作为每个环境的受保护密钥存储，并只授予部署作业所需的访问权限。
B. 将两套凭据都存储在应用的源代码仓库中，以确保部署一致。
C. 在 staging 和 production 中使用同一套管理员凭据，以避免认证差异。
D. 将凭据直接嵌入 Docker 镜像中，使同一镜像包含部署所需的一切。

答案：A
解析：凭据应按环境分别作为受保护密钥管理，遵循最小权限原则，避免泄露与越权。
