DevOps and MLOps 测验 ================================================================


第 2 题
题目：为什么容器通常比运行独立客户机操作系统的传统虚拟机更轻量？

A. 容器将整个操作系统打包成更压缩的格式。
B. 容器通常共享宿主操作系统的内核，而不是为每个容器运行独立的客户机内核。
C. 容器避免执行系统进程，因此不需要任何操作系统资源。
D. 容器通过为每个应用分配独立的物理处理器来实现隔离。

答案：B
解析：虚拟机每台都包含一个完整的客户机操作系统及其内核，而容器共享宿主机的内核，
只打包应用及其依赖。因此容器启动更快、占用资源更少，这才是其"轻量"的根本原因。
A 说"压缩"并非关键；C 说不需要系统资源是错误；D 与隔离机制无关。

第 3 题
题目：一个团队想验证客户能否打开网站、登录、将商品加入购物车并通过用户界面完成购买。
哪种测试方法最合适？

A. 端到端测试（End-to-end testing）。
B. 单元测试（Unit testing）。
C. 静态代码分析（Static code analysis）。
D. 组件测试并模拟所有外部依赖（Component testing with all external dependencies mocked）。

答案：A
解析：该场景覆盖从打开网站到完成购买的完整用户流程，穿越多个组件（前端、登录、
购物车、支付），属于典型的端到端测试。单元测试只测单个函数；静态分析不运行代码；
组件测试且模拟所有依赖无法验证真实的完整流程。

第 4 题
题目：开发人员测试一个根据客户购买金额计算折扣的函数。测试提供不同的输入并验证返回值，
而不访问数据库或外部服务。这是哪种测试？

A. 集成测试（Integration testing）。
B. 端到端测试（End-to-end testing）。
C. 单元测试（Unit testing）。
D. 验收测试（Acceptance testing）。

答案：C
解析：测试只针对一个函数、提供不同输入并检查返回值，且不涉及数据库或外部服务，
是隔离的最小单元验证，属于单元测试。集成测试会涉及多个组件交互；端到端测试覆盖
完整流程；验收测试面向业务需求验收。

第 5 题（多选）
题目：一个团队想确保只有在自动化测试通过后才进行部署。哪些工作流设计可以实现这一点？

A. 在 YAML 文件中将部署作业定义在测试作业之后，但不声明依赖关系。
B. 创建独立的测试作业和部署作业，部署作业通过 needs 依赖测试作业。
C. 将部署作业命名，使其按字母顺序排在最后。
D. 将测试和部署作为同一作业中的顺序步骤运行，依赖"前序失败则后续步骤被跳过"的默认行为。

答案：B、D
解析：B 通过在作业间声明 needs 依赖，确保测试成功后才触发部署；D 在同一作业内按顺序
执行步骤，前一步失败则后续步骤自动跳过，从而部署不会执行。A 仅靠书写顺序不构成依赖，
无法保证；C 按字母排序与执行逻辑无关。

第 6 题（多选）
题目：在协作开发中，特性分支（feature branches）能带来哪些好处？

A. 允许开发人员在不立即修改主分支的情况下进行更改。
B. 允许某个特性或应用的多个版本并行开发。
C. 保证独立开发的更改在合并时不会产生冲突。
D. 自动阻止带有失败测试的代码被合并。

答案：A、B
解析：特性分支的核心价值是隔离开发：不直接影响主分支（A），并可并行推进多个特性或
版本（B）。分支本身并不保证无冲突（C 错），也不会自动拦截失败测试的合并（D 错，
那需要 CI 保护规则）。

第 7 题（多选）
题目：应用有一个需求：用户不得查看其他用户的私有订单。哪种测试最直接地验证该需求？

A. 验证用户能成功检索自己的订单。
B. 验证数据库架构包含标识订单所有者的列。
C. 以一个用户身份认证，尝试检索另一用户的私有订单，并验证访问被拒绝。
D. 验证未认证的访客无法在首页看到订单菜单。

答案：C
解析：只有真正尝试越权访问（以用户身份去取他人订单）并确认被拒绝，才直接验证了
"不得查看他人订单"这一访问控制需求。A 只测正常情况；B 只验证结构不验证行为；
D 针对的是未认证访客，与用户间越权无关。

第 8 题（多选）
题目：哪些陈述正确地描述了 docker build 和 docker run？

A. docker build 会为 Dockerfile 中的每条指令启动一个正在运行的容器，并在构建后保持其运行。
B. docker build 使用构建上下文和诸如 Dockerfile 中的指令来构建 Docker 镜像。
C. docker run 在执行应用前总是重新构建镜像。
D. docker run 从镜像创建并启动一个容器。

答案：B、D
解析：docker build 读取构建上下文并按 Dockerfile 指令生成镜像（B 对）；构建过程中临时
容器的中间层不会作为运行容器保留（A 错）。docker run 从已有镜像创建并启动容器，
并不会重新构建镜像（D 对，C 错）。

第 9 题
题目：两位开发人员在不同分支上独立修改了同一文件的同一部分。为什么 Git 会产生合并冲突？

A. Git 不允许两个人在不同分支上修改同一文件。
B. Git 要求两个分支包含完全相同的提交数量。
C. Git 无法自动确定如何合并重叠的修改。
D. 只要分支历史分叉，Git 就拒绝合并分支。

答案：C
解析：当两个分支对同一位置的修改发生重叠时，Git 的三方合并无法自动判断应保留哪些内容，
于是标记为冲突交由人工解决。Git 允许不同分支修改同一文件（A 错），与提交数量无关（B 错），
历史分叉本身也会被正常合并（D 错）。

第 10 题
题目：一个应用使用某个服务将客户信息保存到数据库中。一个测试调用该服务，使用真实的测试
数据库，并验证信息被正确存储。这最恰当地代表哪种测试？

A. 单元测试，因为只调用了一个服务方法。
B. 集成测试，因为验证的是应用代码与数据库之间的交互。
C. 端到端测试，因为数据经过多个软件组件。
D. 静态测试，因为测试检查了存储数据的结构。

答案：B
解析：测试关注的是应用代码与真实数据库之间的交互是否正常，属于集成测试。虽然只调用
一个方法，但涉及了外部依赖（数据库），因此不是单元测试；也不是覆盖完整用户流程的
端到端测试；静态测试不运行代码。

第 11 题
题目：哪项陈述最好地解释了 Docker 镜像与 Docker 容器之间的关系？

A. 镜像是正在运行的应用，而容器是用于构建它的文件。
B. 镜像和容器是同一资源的可互换名称。
C. 镜像是可复用的模板，而容器是从该镜像创建的实例。
D. 容器用于构建镜像，但镜像不能复用来创建额外的容器。

答案：C
解析：镜像是只读的、可复用的模板，容器是其运行实例，一个镜像可创建多个容器。
A、B、D 的表述均颠倒或错误。

第 12 题
题目：一个团队希望每当新提交被推送到仓库时就执行 GitHub Actions 工作流。他们应使用哪种配置？

A. on: workflow_dispatch
B. on: pull_request
C. on: push
D. on: schedule

答案：C
解析：on: push 在向仓库推送提交时触发，符合需求。workflow_dispatch 为手动触发；
pull_request 在 PR 事件时触发；schedule 按定时计划触发。

第 13 题（多选）
题目：一个项目在一位开发人员的笔记本上通过测试，但在 GitHub Actions 中因环境不同而失败。
哪些做法有助于让执行更具可复现性？

A. 依赖安装在开发人员本机上的工具，而不是在 CI 中声明它们。
B. 只要仓库中有之前成功的工作流运行，就跳过环境设置。
C. 使用合适的依赖管理和锁文件（lockfile）固定依赖版本。
D. 在工作流中显式配置所需的编程语言和运行时版本。

答案：C、D
解析：固定依赖版本（C）和显式声明语言/运行时版本（D）能消除"我这里能跑"的环境差异，
提升可复现性。依赖本机工具（A）和跳过环境设置（B）都会加剧环境不一致。

第 14 题
题目：为什么传统测试金字塔建议单元测试数量多于端到端测试？

A. 单元测试能识别集成测试和端到端测试能检测到的所有可能问题。
B. 当应用有足够的单元测试覆盖率时，端到端测试就不必要了。
C. 应避免集成测试，因为它们与单元测试功能重复。
D. 单元测试通常更快、更便宜且更易于隔离，而端到端测试提供更广但更昂贵的覆盖。

答案：D
解析：金字塔的底层放大量单元测试，是因为它们运行快、成本低、易隔离、反馈迅速；
上层端到端测试覆盖更广但慢且昂贵，因此数量应少。A、B、C 都是对金字塔的误解。

第 15 题
题目：考虑以下 Dockerfile 指令：
    RUN npm install
    CMD ["node", "server.js"]

A. RUN 每次容器启动时执行，而 CMD 仅在构建镜像时执行。
B. 两者都在镜像构建期间执行，但 CMD 专用于生产应用。
C. 两者都在容器启动时执行，但 RUN 总是在 CMD 之前执行。
D. RUN 在镜像构建期间执行，而 CMD 指定容器启动时的默认命令。

答案：D
解析：RUN 在镜像构建阶段执行（如安装依赖，其结果固化进镜像层）；CMD 不会在构建时执行，
而是指定容器启动时的默认命令。A、B、C 对执行时机的描述均错误。

第 16 题
题目：一个工作流需要私有 API 令牌来部署应用。提供该令牌最合适的方式是什么？

A. 将其存储为 GitHub Actions 密钥（secret），并仅暴露给需要它的步骤。
B. 将其添加到提交到仓库的配置文件中。
C. 将其存储在仓库变量中，因为变量像密钥一样会被加密。
D. 直接包含在工作流 YAML 中，以便部署可复现。

答案：A
解析：敏感凭证应存为 GitHub Actions secret 并仅按需暴露，避免泄露。写入仓库文件（B）或
明文 YAML（D）都会暴露密钥；仓库变量（C）默认不加密，不适合存放机密。

第 17 题（多选）
题目：单元测试通常应具备哪些理想特征？

A. 它们总是需要真实的生产数据库来保证结果真实。
B. 它们验证小段逻辑，并在适当时控制或隔离外部依赖。

第 18 题（多选）
题目：关于 Dockerfile 指令的哪些陈述是正确的？

A. FROM 指定构建阶段的基础镜像。
B. EXPOSE 会自动将容器的端口发布到宿主机上。
C. RUN 在构建镜像时执行命令。
D. CMD 指定容器启动时要执行的默认命令。

答案：A、C、D

发布需要 docker run -p（B 错）。

第 19 题
题目：为什么保留那些针对已实现并已验证特性的自动化测试是有用的？

A. 当后续更改意外破坏了此前正常工作的行为时，它们能检测到回归。
B. 它们确保未来永远不需要任何修改。

D. 它们保证所有新引入的代码都无缺陷。

答案：A

第 20 题（多选）
题目：哪些示例最适合归类为集成测试？

A. 测试某个仓库类能否正确地向真实测试数据库保存和检索数据。
B. 测试一个将字符串转换为大写的纯函数。
C. 将网页的按钮布局与静态设计截图进行比对检查。
D. 测试某个服务能否正确地向真实测试消息代理（message broker）发布消息。

答案：A、D
解析：A（代码与真实数据库交互）和 D（服务与真实消息代理交互）都验证多个组件/外部依赖
之间的协作，属于集成测试。B 是纯函数的单元测试；C 是 UI 检查，不属于集成测试。

第 21 题
题目：一个测试单独执行时始终通过，但在其他测试之后执行时有时失败。最可能的根本问题是什么？

A. 应用被测试覆盖的代码行太少。
B. 测试可能依赖共享状态或其执行顺序。
C. 失败测试的预期输出一定是错误的。
D. 该测试一定是在针对过时的应用版本运行。

答案：B
解析：单独通过、与他测共跑失败，是典型的测试间依赖共享状态或执行顺序导致的"测试污染"
问题。覆盖率低（A）、预期输出错误（C）、版本过时（D）都无法解释"单独执行能通过"这一现象。

题目：为什么创建独立的特性分支通常比直接在主分支上开发更可取？

第 23 题（多选）
题目：一位同事在你本地开发期间向远程分支推送了更改。哪些方法可以将那些远程更改集成到你
当前的分支中？

A. 使用合适的集成策略运行 git pull。
B. 只运行 git fetch 而不做任何额外操作。
C. 运行 git fetch，然后将相应的远程跟踪分支合并到你的当前分支中。
D. 运行 git status 来同步远程和本地历史。

答案：A、C
解析：git pull 相当于 fetch 加合并/变基（A 对）；先 fetch 再手动合并远程跟踪分支也能把
远程更改并入本地（C 对）。只 fetch 只是更新远程跟踪引用，不会改动你的当前分支（B 错）；
git status 只显示状态，不会同步历史（D 错）。

第 24 题
题目：一位开发人员在本地提交了更改，但他的同事从共享仓库拉取后看不到这些更改。最可能的
原因是什么？

A. 同事需要在拉取前创建新的本地分支。
B. 开发人员尚未将提交推送到远程仓库。
C. 开发人员尚未将更改合并到默认分支。

第 25 题（多选）
题目：哪些 Git 操作可以在不联系远程服务器的情况下在本地仓库上执行？

第 26 题
题目：一个应用在其 Docker 容器内监听端口 3000。开发人员想通过宿主机的端口 8080 访问它。
使用 docker run 时应采用哪个选项？

A. -p 3000:8080
B. --expose 8080
C. -p 8080:3000
D. --network 8080:3000

答案：C
解析：端口映射格式为 主机端口:容器端口，将宿主机 8080 映射到容器 3000 应为 -p 8080:3000。
A 顺序颠倒；--expose 只是声明端口不发布；--network 用于指定网络而非端口映射。
